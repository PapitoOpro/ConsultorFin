# Redesign da interface (Dark Fintech Premium): Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Modernizar a interface do ConsultorFin com a identidade "Dark Fintech Premium" (referência visual: dashboard Vault), preservando todas as funcionalidades, regras financeiras e dados reais.

**Architecture:** O pedido do dono (briefing de 26/10/2026) foi escrito supondo Streamlit/Supabase/Plotly; o app real é **FastAPI + Jinja2 + HTMX + ECharts + SQLite**, então o redesign é feito em CSS/templates/JS locais (sem CDN, sem novas dependências). Tokens de design centralizados em `tema.css`; um tema ECharts reutilizável em JS; macros Jinja para ícones e componentes; o dashboard ganha novos blocos alimentados por consultas somente leitura sobre as regras existentes.

**Tech Stack:** Python 3.11+, FastAPI/Jinja2/HTMX, ECharts vendorizado, CSS puro, ícones Lucide (ISC) embutidos como SVG inline, pytest, Chrome DevTools MCP para verificação visual.

**Spec:** o briefing do dono (resumido em "Decisões") e a imagem de referência em `.superpowers/referencia/vault.png` (fora do Git). Regras do projeto em `CLAUDE.md`.

## Decisões

- **Adaptação ao stack real:** onde o briefing fala de Streamlit/Supabase/Plotly/`st.columns`, vale o equivalente no app real. Nada de autenticação ou Supabase aqui; nenhuma regra financeira, consulta existente, esquema de banco ou cálculo muda.
- **Paleta** (substitui a de `CLAUDE.md` seção 5, que deve ser atualizada para os novos tokens): fundo `#080912`, sidebar `#0D0D19`, cards `#111120`, secundário `#171728`, bordas `#242438`, texto `#F5F5FA`, texto secundário `#9292AB`, texto auxiliar `#6D6D88`, marca/positivo `#00D6A0`, azul `#4DA3FF`, negativo `#FF5470`, alerta `#FFB84D`, roxo `#A78BFA`. Manter os NOMES de variável existentes (`--fundo`, `--superficie`, `--borda`, `--primaria`, `--alerta`, `--entrada`, `--saida`, `--texto`, `--texto-secundario`) apontando para os novos valores e acrescentar `--fundo-menu`, `--superficie-2`, `--texto-auxiliar`, `--info`, `--roxo`, `--raio` (14px), `--raio-pequeno` (10px), `--sombra`, `--transicao`. Ajustar tons só se o contraste de texto ficar abaixo de 4,5:1 (conferir).
- **Tipografia:** manter Inter e JetBrains Mono já vendorizadas (sem nova fonte): títulos e valores em Inter 600–700; valores monetários em tabelas continuam em JetBrains Mono alinhados à direita (regra do projeto); números grandes dos cards em Inter 700 com `font-variant-numeric: tabular-nums`.
- **Ícones:** Lucide (ISC) copiados como SVG inline para um macro `icone(nome)` em `app/web/templates/_icones.html`, com os ícones realmente usados; aviso de licença em `app/web/static/THIRD_PARTY.txt`. Sem emojis na interface principal.
- **O que NÃO entra (não há funcionalidade real por trás):** avatar, sino de notificações, busca global, saudação personalizada, metas de economia, cartões, análises. Nenhuma página nova. Os filtros reais (mês e horizonte) continuam como estão, só mais bonitos.
- **Dados novos no dashboard (somente leitura, reaproveitando as regras existentes):** série de 6 meses de entradas e saídas para o fluxo de caixa (usa `entradas_do_mes`/`despesas_do_mes` mês a mês), últimos lançamentos efetivados, próximos vencimentos (pendentes de saída ordenados por data, vencidas primeiro). Comparações percentuais nos cards (Entradas e Saídas contra o mês anterior) só quando o mês anterior for maior que zero; Saldo total e Resultado sem comparação.
- **Responsivo:** sidebar fixa de 232 px a partir de 1000 px; abaixo disso vira barra superior com botão de menu (sem depender de JS pesado: `<details>` ou checkbox CSS); grade de cards 4→2→1 colunas; gráficos lado a lado (65/35) viram coluna única; tabelas largas rolam dentro do próprio contêiner (nunca rolagem horizontal da página inteira).
- **Acessibilidade:** foco visível, contraste ≥ 4,5:1 no texto, `prefers-reduced-motion` desliga animações, estados nunca só por cor (sinal +/−, setas ou texto).
- **Sombras:** o briefing passa a permitir sombras suaves (a regra antiga "sem sombras" de `CLAUDE.md` seção 5 é atualizada).
